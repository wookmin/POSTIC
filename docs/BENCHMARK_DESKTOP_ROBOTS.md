# 탁상용 제품·연구 로봇 벤치마크

조사 기준: 2026-10-02

이 문서는 Notifyi를 평가하는 문서가 아니다. 공개된 탁상용 제품과 연구용 로봇이 어떤 하드웨어·상호작용·소프트웨어 구조를 사용하는지 조사하고, 향후 비교 기준으로 쓸 항목과 적용 후보를 분리해 기록한다.

## 1. 조사 대상 분류

탁상용 로봇은 크게 네 종류로 나뉜다.

| 유형 | 대표 사례 | 중심 가치 |
| --- | --- | --- |
| 데스크톱 펫 | EMO, Eilik | 짧고 빈번한 감정 표현, 친밀감 |
| 이동형 홈 로봇 | Vector, Loona | 자율 이동, 주변 인식, 능동적 접근 |
| 사회·교육 로봇 | Moxie, QTrobot | 대화, 교육·치료 프로그램, 장기 상호작용 |
| 연구용 표현 플랫폼 | Furhat, SPRITE, Patricc | 빠른 행동 제작, 실험 반복성, 모듈성 |

제품과 연구 플랫폼은 목적이 다르다. 제품은 첫인상·반복 사용·서비스 안정성을 중요하게 보고, 연구 플랫폼은 센서 교체·행동 authoring·데이터 수집·재현성을 중요하게 본다.

## 2. 상용 제품 사례

### 2.1 EMO — LivingAI

공식 자료에서 확인되는 특징:

- 책상 위에서 독립적으로 움직이는 데스크톱 펫
- HD 카메라와 얼굴 인식
- 4개 마이크 배열과 소리 방향 인식
- 머리 터치 센서
- 스피커와 표정·동작을 결합한 반응
- 1,000개 이상의 표현과 동작을 강조
- 낙하를 피하고 책상 위를 탐색하는 자율성

참고:

- [EMO 공식 제품 페이지](https://living.ai/emo/)
- [EMO 공식 사양](https://living.ai/emo-specs/)

벤치마크 포인트:

- 단일 모터 동작보다 얼굴·소리·터치·이동을 묶은 짧은 반응 단위가 중요하다.
- 제품의 개성은 센서 수 자체보다 입력에 대한 표현 레퍼토리와 전환 타이밍에서 형성된다.
- 탁상용 이동 로봇은 낙하 방지와 책상 경계 인식이 기능의 전제다.

### 2.2 Eilik — Energize Lab

공식 자료에서 확인되는 특징:

- 4개의 서보
- 1.54인치 OLED
- 머리·몸통의 터치 반응
- 진동·충격에 대한 반응
- 3W 스피커
- USB-C, 소형 배터리
- 자석 손과 외형·소품을 통한 캐릭터 확장
- 표정과 감정 상태를 전면 디스플레이로 표시

참고:

- [Eilik 공식 소개와 사양](https://www.energizelab.com/eilik/)

벤치마크 포인트:

- 작은 기구라도 화면·터치·진동을 결합하면 상호작용 입력이 풍부해진다.
- 제품 외형과 소품을 바꾸는 방식은 소프트웨어 업데이트만으로 만들기 어려운 재방문 동기를 만든다.
- 저가·소형 제품은 고자유도 기구보다 명확한 캐릭터 동작과 물리적 접촉 반응을 우선한다.

### 2.3 Vector — Anki / Digital Dream Labs

공개 자료에서 확인되는 특징:

- HD 광각 카메라
- 4개 마이크 배열과 beamforming
- 적외선 레이저 스캐너
- 6축 IMU
- 하향식 낙하 감지 센서
- 컬러 디스플레이
- 자율 이동과 장애물·사람·물체 인식
- 카메라·음성 스트리밍에 대한 사용자 표시와 제어

참고:

- [Vector 공식 제품 페이지](https://anki.bot/vector)
- [Vector 음성 인식과 마이크 배열](https://support.anki.bot/article/111-video-vector-and-speech-recognition)
- [Vector 보안·프라이버시 FAQ](https://support.anki.bot/article/105-vector-security-privacy-faqs)

벤치마크 포인트:

- 카메라가 있는 제품은 카메라가 켜져 있거나 데이터를 처리하는 상태를 사용자에게 알려야 한다.
- 자율 이동보다 먼저 낙하·충돌·충전 복귀 같은 탁상 환경 안전을 해결한다.
- 온보드 처리, 클라우드 처리, 저장 여부를 기능별로 분리해 설명한다.

### 2.4 Loona — KEYi Technology

공식 자료에서 확인되는 특징:

- 3D ToF LiDAR를 이용한 내비게이션·장애물 회피
- 모바일 앱 원격 제어
- 반려동물형 외형과 움직임
- 카메라·상호작용을 결합한 주변 인식 방향

참고:

- [Loona 공식 소개](https://robotloona.com/about/)
- [KEYi Technology 공식 소개](https://www.keyirobot.com/about-us)

벤치마크 포인트:

- 이동형 탁상 로봇은 비전만으로 해결하지 않고 거리 센서를 추가해 책상 환경의 실패 모드를 줄인다.
- 제품 정체성은 기능 목록보다 이동 방식, 시선, 몸짓의 일관성으로 전달된다.
- 원격 제어는 자율 기능이 실패했을 때의 사용성 보완책이 될 수 있다.

### 2.5 Moxie — Embodied

공식 자료와 연구 자료에서 확인되는 특징:

- 움직이는 팔과 회전하는 몸통
- 감정 반응형 HD 카메라
- body language와 eye contact를 대화 시스템과 결합
- 보호자 앱과 장기 커리큘럼
- 사회·정서 학습을 위한 반복 세션 구조

참고:

- [Moxie 공식 제품 페이지](https://www.moxierobot.com/products/moxie-replacement)
- [Social and Emotional Skills Training with Embodied Moxie](https://arxiv.org/abs/2004.12962)

벤치마크 포인트:

- 동작은 단독 애니메이션보다 대화·시선·콘텐츠의 맥락 안에서 의미가 생긴다.
- 장기 사용 제품은 첫날의 신기함보다 반복 세션에서의 목표·기억·콘텐츠 구조가 중요하다.
- 클라우드 의존 제품은 서비스 중단 시 사용자 경험과 감정적 신뢰가 함께 손상될 수 있으므로, 핵심 동작의 오프라인 fallback이 필요하다.

## 3. 연구·개발 플랫폼 사례

### 3.1 Furhat

Furhat은 얼굴을 후면 투사하는 방식의 사회적 로봇 플랫폼이다.

공개 자료에서 확인되는 특징:

- 투사형 얼굴을 통한 표정·시선·캐릭터 변경
- 여러 사용자를 대상으로 한 얼굴 추적
- 음성, 표정, 행동을 skill 단위로 개발
- SDK, 예제, 개발자 도구, 분석 도구 제공
- 연구 목적에 따라 외형·나이·성별·캐릭터를 바꿀 수 있음

참고:

- [Furhat Developer Zone](https://furhat.io/)
- [Furhat Robotics](https://www.furhatrobotics.com/)

벤치마크 포인트:

- 하드웨어보다 행동 authoring과 디버깅 도구가 연구 플랫폼의 핵심 가치가 될 수 있다.
- 표정·시선·음성·몸짓을 하나의 skill로 묶으면 실험 조건을 재현하기 쉽다.
- 캐릭터 변경 가능성은 기구를 바꾸지 않고도 사용자 반응을 비교하게 한다.

### 3.2 QTrobot — LuxAI

QTrobot은 교육·치료·사회적 상호작용 연구를 위한 플랫폼이다.

공개 자료에서 확인되는 특징:

- NVIDIA Jetson 기반 엣지 AI 구성을 제공하는 제품군
- Intel RealSense D455 깊이 카메라
- 포즈·행동·얼굴·물체 인식
- 30개 이상의 얼굴 표현을 표방
- ROS API와 Python, C++, JavaScript 개발 경로
- 블록 기반 Studio와 연구용 SDK
- 연구자가 빠르게 행동을 구성하는 authoring 환경

참고:

- [QTrobot 연구 플랫폼](https://luxai.com/product/qtrobot-research-platform)
- [QTrobot 공식 문서](https://docs.luxai.com/)

벤치마크 포인트:

- 지각·행동·콘텐츠를 분리한 SDK가 연구 반복성을 높인다.
- 깊이 센서는 단일 RGB 카메라가 취약한 거리·가림 문제를 보완한다.
- 비전문가도 행동을 수정할 수 있는 authoring 도구가 연구팀의 병목을 줄인다.

### 3.3 SPRITE — Stewart Platform Robot for Interactive Tabletop Engagement

SPRITE는 탁상용 사회적 보조 로봇 연구 플랫폼이다.

논문에서 확인되는 특징:

- Stewart platform으로 x, y, z, roll, pitch, yaw 6자유도 표현
- 약 30cm 높이의 탁상 크기
- 커스텀 스킨과 의상으로 외형 변경
- 오프보드 컴퓨팅
- 부품 교체와 수리를 고려한 기계 설계
- 비상 정지 버튼
- keyframe 애니메이션과 Bezier 보간
- ROS 기반 CoRDial 소프트웨어
- 동작·음성·얼굴 움직임을 동기화하는 구조

참고:

- [SPRITE 원 논문](https://arxiv.org/abs/2011.05786)

벤치마크 포인트:

- 자유도 증가 자체보다 keyframe과 보간을 통한 표현 동작 설계가 중요하다.
- 탁상용 제품은 안전·수리·외형 변경을 초기 설계 목표에 포함해야 한다.
- 오프보드 컴퓨팅은 본체를 단순화하고 연구 반복 속도를 높인다.
- 연구 플랫폼에서는 모터 제어 API보다 행동을 빠르게 저작하는 계층이 중요하다.

### 3.4 Patricc

Patricc은 부모·유아·로봇의 삼자 상호작용을 연구하기 위한 플랫폼이다.

논문에서 확인되는 특징:

- 3D 프린트 skeleton 위에 교체 가능한 puppet character
- 물리적 소품을 이용한 캐릭터 변화
- 비전문가를 위한 행동 authoring 도구
- 태블릿과 비교해 부모·유아·로봇 사이의 시선 상호작용을 연구

참고:

- [Patricc 원 논문 정보](https://ieeexplore.ieee.org/document/9484268/)

벤치마크 포인트:

- 외형을 바꾸는 구조는 사용자의 해석과 상호작용 맥락을 바꾼다.
- 연구용 로봇은 연구자가 동작을 직접 작성할 수 있어야 한다.
- 로봇 단독 상호작용이 아니라 주변 사람과의 삼자 상호작용을 고려한다.

### 3.5 Cozmo — 반복 상호작용 연구 사례

Cozmo는 제품이지만, 실제 가정에서 감정 표현을 어떻게 해석하는지 연구된 사례가 있다.

연구에서 확인된 점:

- 사용자는 로봇의 표정·소리·행동을 한 가지 감정으로만 해석하지 않는다.
- 같은 표현도 상호작용 맥락에 따라 의미가 달라질 수 있다.
- 슬픔 표현은 사용자가 자신의 이전 행동을 되돌아보게 하는 상호작용 효과를 만들 수 있었다.

참고:

- [Are You Sad, Cozmo?](https://ieeexplore.ieee.org/document/9484308/)

벤치마크 포인트:

- 표현의 모호성은 친밀감을 만들 수 있지만, 안전·자세 피드백처럼 목적이 명확해야 하는 기능에는 모호성이 위험할 수 있다.
- 표현 동작의 의미를 사용자가 어떻게 해석했는지 반드시 별도로 검증한다.

## 4. 외부 사례에서 유지할 벤치마크 기준

향후 어떤 탁상용 로봇을 조사하더라도 다음 항목을 동일하게 기록한다.

### 입력

- 카메라 종류와 위치
- 깊이 센서·LiDAR·IMU·터치·마이크
- 온보드 처리와 클라우드 처리 구분
- 사용자의 입력 상태를 알리는 표시

### 표현

- 자유도와 실제 표현 가능한 축
- 얼굴·화면·몸통·팔·이동의 조합
- keyframe 또는 궤적 authoring 가능 여부
- 속도·가속도·pause·시선·회복 동작

### 상호작용

- 반응형인지 선제형인지
- 개입 타이밍을 어떻게 정하는지
- 반복 사용에서 콘텐츠가 어떻게 변하는지
- 사용자가 무시하거나 거부할 수 있는지

### 공학

- 낙하·충돌·과부하 방지
- 비상 정지
- 배터리·전원·열
- 수리·교체·케이블 관리
- 오프라인 동작과 서비스 중단 대응

### 연구 재현성

- SDK·시뮬레이터·예제
- 로그·리플레이
- 행동 authoring 도구
- 센서와 모터 추상화
- 설정 프로파일

## 5. 향후 Notifyi 적용 후보

아래는 외부 사례에서 도출한 적용 후보이며, 현재 구현 완료를 의미하지 않는다.

### 우선 적용 후보

1. fixed pose 대신 keyframe 기반 motion primitive
2. 관절 수와 무관한 robot profile
3. 표현 동작의 속도·pause·진입·회복 파라미터
4. 사용자 작업 중 개입 가능성 추정
5. 관측 상태·카메라 처리 상태 표시
6. 모터 그룹·카메라 그룹·표정 그룹의 capability 분리
7. 부품 교체와 수리를 고려한 모듈식 외장·브라켓
8. 오프라인에서도 안전 동작과 로그가 가능한 구조

### 후순위 적용 후보

- 화면 기반 표정
- 음성·마이크 배열
- 깊이 카메라
- 탁상 이동
- 사용자별 캐릭터 스킨
- 학습 기반 행동 생성

## 6. 적용하지 않고 관찰만 할 항목

- LLM이 모터 목표를 직접 생성하는 구조
- 제품의 감정 표현을 자세 교정 의미로 그대로 사용하는 방식
- 클라우드 연결이 끊기면 핵심 동작이 불가능한 구조
- 무작위 개입으로 사용자의 주의를 계속 끄는 방식
- 고자유도 모터를 먼저 늘리고 안전·서비스 구조를 나중에 정하는 방식
