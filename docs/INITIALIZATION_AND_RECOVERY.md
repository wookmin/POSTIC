# Notifyi 초기화와 복구

## 현재 상태

복구 초기화는 현재 메인 실행 경로가 아니다. --initialize 또는 --recover를 실제 운용 시작 전에 자동으로 호출하지 않는다.

이 기능을 메인에 넣기 전에 해결해야 할 문제가 있다.

- 일부 모터는 위치 제어가 아니라 속도 제어 모드일 수 있다.
- ID 9 목 모터에서 과부하 오류가 발생한 이력이 있다.
- 물리적으로 누워 있는 상태에서 모든 관절을 동시에 zero로 보내면 하중이 아래 관절에 집중될 수 있다.
- 토크 해제와 현재 위치 읽기가 일부 관절에서 실패할 수 있다.
- zero_position은 모든 자세에서 도달 가능한 안전 위치가 아니라, 세워진 기준 자세의 설정값이다.

## 용어

zero_position은 로봇이 실험을 시작할 때 기준으로 삼는 Dynamixel tick이다. 현재 설정에서는 다음 값이 사용된다.

- base_pitch: 2033
- waist_pitch: 2041
- spine_lower_pitch: 2044
- spine_upper_pitch: 2046
- neck_pitch: 3018

이는 모터의 절대적인 물리적 원점이나 누워 있는 로봇을 자동으로 일으키는 만능 복구점이 아니다. 모터별 기계적 범위와 장착 방향을 함께 확인해야 한다.

## 메인 동작 전 현재 안전 절차

1. 로봇을 손으로 세워 각 관절을 운용 범위 안에 둔다.
2. scan_dynamixel.py로 ID, 동작 모드, 토크, hardware error, 현재 위치를 확인한다.
3. 과부하 오류가 있으면 하중을 줄인 뒤 오류를 해제한다.
4. src.main의 메인 동작을 dry-run으로 먼저 확인한다.
5. 이상이 없을 때만 --move를 붙인다.

복구 테스트는 별도 스크립트와 테스트에서만 검증하고, 실제 하드웨어에서는 관절별 단독 이동, 정지 조건, 토크 해제, 전원 차단을 각각 확인한다.

## 향후 복구 순서

자동 복구를 다시 설계한다면 전체 관절 병렬 이동보다 다음 순서를 우선한다.

1. 버스와 모터 응답 확인
2. 하드웨어 오류·온도·전압·토크 상태 확인
3. 현재 위치와 운용 범위 확인
4. 하중을 받는 하단 관절부터 아주 작은 step으로 이동
5. 각 단계마다 위치·전류·오류를 재확인
6. 목 관절은 컬럼이 안정된 뒤 마지막에 이동
7. zero_position 근처 도달 후에도 토크 상태와 기구 안정성을 확인
8. 실패한 관절이 있으면 나머지 정리와 안전 정지를 독립적으로 수행

초기화 기능을 메인 실행에 추가하는 것은 실제 하드웨어 검증과 별도 승인 이후의 작업이다.
