# Notifyi 자세 인식과 카메라 배치

## 1. 현재 인식의 전제

현재는 로봇에 탑재한 단일 RGB 카메라를 중심으로 실험하고, 노트북 웹캠을 보조 입력으로 사용한다.

- MediaPipe Pose Landmarker lite
- 입력 기본값: 640 x 480
- 사람 visibility가 낮으면 unknown
- 중앙값 필터와 지수 평활 적용
- 사용자별 캘리브레이션 없이 실행
- 자세 값은 의학적 신체 각도가 아니라 영상 기반 proxy 값

정면 단일 카메라는 앞뒤 굽힘의 깊이를 안정적으로 측정하기 어렵다. 따라서 설정의 torso_pitch_deg, neck_pitch_deg, lateral_tilt_deg를 실제 관절 각도로 해석하거나 의료적 자세 점수로 사용하지 않는다.

## 2. 카메라 위치별 권장

| 배치 | 장점 | 주요 위험 | 현재 판단 |
| --- | --- | --- | --- |
| 노트북 웹캠 | 즉시 테스트 가능 | 로봇과 사용자의 상대 위치가 달라짐 | 보조 검증 |
| 로봇 상단 정면 | 제품 구조와 일치 | 로봇이 굽으면 시야가 함께 변함 | 주 실험 |
| 사용자 측면 | 앞뒤 굽힘에 유리 | 설치 공간·가림 문제 | 인식 검증용 |
| 측면 깊이 카메라 | 거리 정보 확보 | 가격·무게·조명 영향 | 후순위 |

카메라를 옮긴 뒤에는 임계값만 다시 조절하지 말고, 정상·앞으로 숙임·고개 숙임·좌우 기울임·가림을 포함한 짧은 검증 영상을 다시 수집한다.

## 3. 탑재 카메라 안정화

로봇이 나쁜 자세 포즈를 실행할 때 몸통이 회전하면 카메라도 같이 움직일 수 있다. 현재는 neck_pitch를 몸통 변화량의 반대 방향으로 보정하는 단순 짐벌 효과를 사용한다.

이 보정은 다음을 보장하지 않는다.

- 카메라 영상의 실제 픽셀 흔들림 제거
- 사용자의 머리와 카메라 사이 거리 유지
- yaw·roll 변화 보정
- 링크 유격과 가속도에 대한 보상

검증 순서는 카메라를 고정한 뒤, 정상 자세 영상과 개입 포즈 영상을 각각 녹화하고 다음을 비교하는 것이다.

1. 사용자의 얼굴·어깨 랜드마크가 프레임에서 얼마나 이동했는가
2. 같은 자세에서 분류 라벨이 바뀌는가
3. 개입 직후 unknown 비율이 증가하는가
4. 짐벌 보정 전후의 false bad, false good 비율이 어떻게 달라지는가

## 4. 캘리브레이션을 최소화하는 방법

현재 목표는 시작 전 별도 캘리브레이션을 없애는 것이다. 대신 아래 조건을 고정한다.

- 카메라 장착 위치와 시야를 물리적으로 고정
- 촬영 해상도와 모델을 실험 중 변경하지 않음
- 카메라 이동 직후에는 자세 판정을 개입 트리거에 사용하지 않음
- 사람이 프레임에 안정적으로 들어온 뒤에만 상태를 시작
- unknown을 정상이나 나쁜 자세로 치환하지 않음

후속으로 필요한 것은 사용자별 캘리브레이션이 아니라 카메라 움직임을 구분하는 안정화 상태다.

~~~text
STABLE -> camera MOVING -> SETTLING -> STABLE
                         \-> posture decision paused
~~~

이 상태가 없으면 짐벌이 움직인 결과를 사용자의 자세 변화로 오인할 수 있다.

## 5. 검증 우선순위

1. 고정 카메라에서 라벨별 오검출 표 작성
2. 로봇 포즈 실행 중 카메라 움직임과 unknown 비율 측정
3. 3초 지속 판정이 프레임 드롭과 가림에 어떻게 반응하는지 측정
4. 측면 카메라 또는 depth 카메라의 필요성 판단
5. 마지막에만 학습 기반 시계열 분류기를 검토

현재 프로토타입에서는 정교한 3D 포즈 모델보다, 같은 입력이 반복될 때 같은 개입이 나오는 결정성과 안전한 관측 중단 처리가 더 중요하다.
